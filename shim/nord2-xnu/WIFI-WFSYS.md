The adapter enforces the six existing always-on predicates (SPM `0x10006304[4:0]=0xd`, `0x1000616c/170[1]=1`, GALS `0x1020e504[0]=1`, AP protections `0x10001228[13]=0`, `0x10001724[2]=0`) before each core operation. After AP and WF ack it performs the selected bounded HOST clock detector at `0x18060000`, timeout IRQ `0x180602d4[0]`, and ack `0x18060184[5]` checks. The deterministic `1/10 us` clock polling follows the accepted AP-wake derivative; it is bounded but is not timing-identical to selected randomized Linux. Source: `mt6893_consys_reg.c:533-616`, `mt6893_pos.c:468-552`, `soc3_0.c:1565-1640`.

The core acquires a new AP `0x180601a0` vote from a full zero word and then a distinct WLAN `0x180601a4[0]` RMW vote. WLAN ack and CFG `0x18001000==0x20010101` precede the five cold reads: WFSYS CPU `0x18000010[0]=0`, top `0x18000000[7]=0`, HOST power `0x180602cc[2]=0`, BGF CPU `0x18000014[0]=0`, BGF top `0x18000008[7]=0`. It re-reads/asserts WFSYS CPU reset, leaving it asserted for the entire run. No inherited powered subsystem is switched off. The AP+WF lifetimes are separate one-shot software references; an initial foreign vote refuses rather than sharing/clearing it.

With the CPU held, the core follows selected `wf_pwr_on_consys_mcu` (`soc3_0.c:2150-2313`): WIFI BPLL then WPLL AFE `0x18003008[21]/[20]` under M2 semaphore20; 30/50 us waits; keyed `0x18000000` power-on; HOST power ack; readability; WF/WFDMA protection `0x18001620/1624[0]` clear and `[3]` acknowledge; VDNR `0x1800e06c[0]`; local WFSYS version `0x184b0010==0x20010000`. AFE is read afresh before each set/clear. The sole-WIFI static vote begins empty; any already-set AFE PLL bit fails closed because this candidate cannot identify another owner's bitmap. Semaphore M2 acquire is one side-effect read at `0x18072050` per try, at most 1,000 tries with 1 us waits; release is `0x18072250=1`. These follow `mt6893.c:447-530`, `mt6893_pos.c:1854-1913`, `mt6893_consys_reg_offset.h:279-281`, `consys_hw.h:39`. A failed/uncertain acquire or release retains `sem20pending`/owned state and halts; there is no retry after an uncertain result.

Successful reverse is a **CPU-held source subset**, not byte-exact restoration: selected `wf_pwr_off_consys_mcu` (`soc3_0.c:2380-2540`) masks WF2CONN idle, protects WF then WFDMA with acknowledgments, clears WFSYS semaphore reset, releases owned WPLL then BPLL under sem20, checks readability, writes keyed power-off and checks HOST ack, unmasks idle, toggles WFSYS EMI request from one read value, clears the owned WF vote, then writes AP wake `0` as the final MMIO. It intentionally omits `conninfra_adie_top_ck_en_off(FW_WIFI)`: this diagnostic never acquired the FW_WIFI top-clock resource or ran firmware. It also omits source debug dumps and coredump waiting. Selected source leaves VDNR set; the transaction is an off/held-CPU result, not a register-for-register rollback. A failed intermediate callback/ack does **not** continue reverse, drop any further vote, or invoke old common cleanup. It retains common ownership and requires manual reset.
