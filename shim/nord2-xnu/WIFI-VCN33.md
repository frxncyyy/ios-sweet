# Nord 2 Wi-Fi VCN33 power control

Opt-in `nord2wifivcn33=1` additionally requires existing persistent/main opt-ins. Disabled preserves previous path. Hook runs on the existing input/PMIF owner immediately after successful persistent phase10, before wake/WFSYS/ROM. This implements the missing selected Linux4.19 MT6893 Wi-Fi PMIC callback, not the separate BT-only raise-voltage callback. Source anchors and corrections are in research/nord2/wifi/combined-backend/vcn33-source-review/REPORT.md, selected kernel04d00c2565764c3922c9b4826b5acff1106e533f.

Fresh preflight captures physical RC10006504 bit0=1 and13 fixed PMIC registers. Both CON0/MON low2 and EN_1 bit15 must be zero, both OP_EN exactly8000, CFG rail1bits6/5 and rail2bit6 zero, both VOSEL selectorF. SharedVS2@18b4 is read-only metadata with no required value. Owner is exact retained phase10 input thread and existing saved/exclusive lifetime/proof, not a caller boolean. No arbitrary PMIC address is admitted.

Five writes only: preserve entire selector words except F→D at1f98/1f9c, then selected source base OP_EN masked updates1be8:8000→8040→8060 and1c0e:8000→8040. Every slot freshly verifies previous fullword and reads fullword back after write. Allother bits including VOCAL preserved. Voltage-first is a deliberate source-order safety refinement under both-off guards; selected Linux configures RC first then voltage. Redundant source CFG clear/SW_LP clear are skipped only because preflight proves them zero and final snapshot confirms unchanged. No SW_EN, sharedVS2, OP_MODE, rollback or retry. Mutation latch precedes possibly committing callback. Any configuration failure retains/manual-reset with existing30s drain before wake/legacy continuation; no teardown.

MON after configuration is observational: RC hardware requests may be absent or dynamic, so no required MON3. Input owner synchronously samples before FORCE_CAL and after N9 FW_READY, in their actual source order. Deferred CAP/normal worker never calls PMIF: it only publishes atomic phases4/5/6(CAP/normal/parked). Input loop samples at most every100ms, at most300 samples in30s from configuration. Initial input setup may delay first periodic sample; no scan-boundary coverage guarantee. Each snapshot has13-register validmask and monotonic timestamp, and phase sampled AFTER register reads. A worker can transition during the read; label is phase-at-print, not exact or uninterrupted scan-state evidence. No shared sample structure is read by worker; owner prints one whole printf line. Periodic read failure logs partial mask then permanently disables sampler without failing healthy backend. Synchronous diagnostic failure stops the chain; no forced physical result.

Snapshot address order:1be2/1be6/1be8/1bee/1bf4/1f98/1c08/1c0c/1c0e/1c14/1c1a/1f9c/18b4. Kinds0preflight,1configured,2precal,3postFWready,4periodic.
